# 경계 사례

기준은 하나다 — **일반 이용자가 "뭔가 달라졌네" 할 변화인가.**
아래는 판단이 갈리기 쉬운 것들을 미리 정리해둔 것이다. 여기 없는 유형은 두 질문으로 돌아가서 판단한다.

1. 내일 앱을 열었을 때 화면·결과·요금·한도 중 하나가 달라지는가
2. 그 차이를 전문용어 없이 한 문장으로 설명할 수 있는가

---

## 싣는다

| 유형 | 예 | 왜 |
|---|---|---|
| 기능이 실제로 켜짐 | 새 기능이 이용자 계정에 보이기 시작 | 화면이 달라진다 |
| 무료·유료 경계 이동 | 유료 전용이던 기능이 무료로 풀림, 또는 그 반대 | 지갑이 달라진다 |
| 사용량 한도 변경 | 하루 몇 회, 업로드 용량, 대화 길이 제한 | 쓰다가 막히던 자리가 달라진다 |
| 가격·요금제 개편 | 구독료 인상, 새 플랜 신설, 플랜 통폐합 | 가장 직접적인 체감 |
| 기본 모델 교체 | 아무 설정 안 해도 답변 품질·속도·말투가 달라짐 | 이용자는 모델명을 몰라도 차이를 느낀다 |
| UI 개편 | 버튼 위치, 메뉴 구조, 앱 첫 화면 변경 | 쓰던 길이 바뀐다 |
| 지역·언어 확대 | 한국에서 안 되던 게 열림, 한국어 지원 시작 | 못 쓰던 사람이 쓰게 된다 |
| 앱·플랫폼 출시 | 모바일 앱, 데스크톱 앱, 브라우저 확장 | 접근 경로가 늘어난다 |
| 기능 제거·종료 | 쓰던 기능이 사라짐, 서비스 종료 예고 | 사라지는 것은 생기는 것만큼 체감된다 |
| 장애·중단 | 몇 시간 접속 불가, 특정 기능 먹통 | 그날 가장 확실한 "달라짐" |
| 정책 변경 | 데이터 학습 사용 여부, 연령 제한, 콘텐츠 규정 | 이용자가 실제로 겪는 조건이 바뀐다 |

## 뺀다

| 유형 | 예 | 왜 |
|---|---|---|
| 예고·로드맵 | "올해 안에 출시 예정" | 오늘 화면에 아무 일도 안 일어난다 |
| 벤치마크·평가 점수 | 어느 모델이 몇 점 | 이용자 체감으로 번역되지 않는다 |
| 논문·연구 발표 | 새 아키텍처, 안전성 연구 | 만드는 사람의 뉴스다 |
| 투자·기업 소식 | 자금 조달, 밸류에이션, 인사이동, 조직 개편 | 서비스가 그대로면 변화가 아니다 |
| 파트너십 체결 | 어느 회사와 협업하기로 | 결과물이 나오면 그때가 뉴스다 |
| API·개발자 전용 | 새 엔드포인트, SDK 버전, 토큰 단가 | 일반 이용자 화면에 안 나타난다 |
| 루머·유출 | 코드에서 발견된 미출시 기능명 | 확정 아니면 오보 위험만 남는다 |
| 소송·규제 진행 | 재판 일정, 조사 착수 | 서비스가 실제로 바뀌기 전까지는 대기 |

## 갈리는 것들 — 조건부

- **API 가격 인하** — 기본은 뺀다. 다만 그것이 이용자 요금제나 무료 한도로 내려온 정황이 확인되면 싣는다
- **새 모델 출시** — 모델 자체가 아니라 **일반 이용자가 앱에서 고를 수 있게 됐는지**가 기준이다.
  선택지에 뜨면 싣고, 발표만 됐으면 뺀다
- **A/B 테스트·일부 노출** — 싣되 🟡로. "일부 이용자에게만 보인다"를 반드시 명시한다
- **국내 서비스** — 이용자 규모가 작아도 한국 독자가 실제로 쓰는 서비스면 싣는다
- **웨이트리스트 오픈** — 기다리는 줄에 서는 것도 이용자가 하는 행동이므로 🟡로 싣는다. 단, 실제 사용 가능 시점은 미확인으로 적는다
- **써드파티 앱에 들어간 AI** — 그 앱을 매일 쓰는 사람이 많으면 싣는다. 발표 자료만 있는 통합은 뺀다

## 자주 하는 실수

- 큰 회사 이름이 나오면 중요해 보이는 착시. 회사 크기가 아니라 **이용자 화면**이 기준이다
- 기술적으로 흥미로운 것과 체감되는 것을 헷갈리는 것. 흥미롭지만 안 보이면 뺀다
- 기사 제목의 "출시"를 그대로 믿는 것. **실제로 켜졌는지** 공식 소스로 확인한다
- 브리핑이 비면 기준을 낮춰서 채우는 것. 빈 날은 비었다고 쓴다
